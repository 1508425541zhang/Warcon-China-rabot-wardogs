# 功能介绍与使用入口

本文汇总当前代码已实现的功能；早期对话和实施计划中的设想不代表已经上线。首次使用先读[安装指南](install.zh-CN.md)。主要管理界面使用简体中文，游戏返回的名称、协议字段和部分原始错误保留原文。

## 服务器管理与玩家数据

基于上游 Warcon，支持多服务器 RCON 管理、组织权限、命令审计、玩家列表、地图、封禁、预留位、自动化和公开状态页。玩家以 SteamID64 区分，昵称变化不改变身份。

玩家详情展示实际可用的击杀、死亡、KD、滚动 180 秒纯步兵 KPM、近 10 分钟峰值和证据。KPM = 最近 180 秒确认的有效纯步兵击杀数 ÷ 3；未知武器、阵营不可靠、队杀、自杀和载具等不冒充纯步兵击杀。资料不完整显示不可用或已确认下限，不把缺失数据当成零。

武器距离图支持切换武器，查看玩家平均击杀距离在全服同武器玩家中的位置；本人同武器有效击杀少于 10 次显示 No／数据不足。距离图供管理员参考，不直接触发处罚。金钱等增长展示依赖面板实际保存的观测，不能恢复停机期间或游戏未提供的数据。

## 五专家委员会

数据分析页新增相邻对局留存：堆叠柱显示上一局玩家的留存人数与流失人数，折线显示留存百分比。按 SteamID 去重，下一局任何时刻再次出现（含返回）即计留存，新玩家不计入分母。支持原有 24 小时／7 天／30 天范围，按下一局开始时间筛选，显示最近 100 次换局；缺少名单显示数据不足，进行中对局为暂定。结果仅反映面板观测，可切换数据表核对。

当前版本 `ensemble-server-round-v3`，详细数学条件见[委员会规则](committee-v3.zh-CN.md)。

| 专家 | 判断依据 |
| --- | --- |
| 击杀节奏 | KPM、独立受害者、短时爆发和击杀间隔；P90 可疑、P95 高度异常 |
| 精准度 | 本局同类枪械至少5杀，按分类爆头率阈值及本服同类分布判断，详见精准度规则 |
| 生涯偏差 | 玩家自身历史，至少 100 个窗口、10 个活跃日，稳健偏差 4／8 与持续条件 |
| 变化点 | 本局各武器有效击杀的变化，至少 20 个完整 15 秒区间；最近 3 段持续上升及 CUSUM 门槛 |
| 持续异常 | 本局及过去 24 小时的独立异常；2 次可疑、3 次高度异常，重叠事件去重 |

每位专家一票；未知不是正常票，也不是异常票。至少 2 票可疑及以上进入观察；至少 3 票可疑及以上或 2 票极可能作弊进入待审核案件；至少 3 票极可能作弊进入自动踢出通道。

委员会另一个直接踢出条件是：**180 秒步兵 KPM 严格大于 4，且击杀节奏之外至少一位专家可疑或高度异常**。还须组织明确开启自动踢出，并通过人数、数据健康、参考样本、版本与频率保护；不要求连续两个或三个 60 秒窗口分别超标。直接动作仍保存证据和执行记录。统计模式及 Shadow 记录中，KPM 严格大于 2 加 6 分。

新安装默认统计影子模式，自动动作默认关闭。Legacy 使用自己的可调分数表及独立实验性踢出／24 小时／7 天隔离开关；切换模式不能把两套条件混用。KD 本身不加社区风控分，但可单独启用下方的服务器硬性数值限制。没有自动永久封禁。

## 证据案件、人工审核与 AI

- 风控首页展示最近 5 个案件；归档页面按页查看更多记录，保留审核状态、原因和处罚关联。
- 人工选择“确认违规并封禁7天”会保存审核结论、写入本服七天封禁，并排队踢出在线玩家。证据不足／误判／数据错误仅保存结论；修改结论不自动解封。详见[人工审核与处罚](case-review-penalty.zh-CN.md)。
- [AI 辅助审查](integrity-ai.zh-CN.md)有独立设置页，可填写兼容 OpenAI 接口的服务地址、密钥和模型；不限定 OpenAI 服务商。Worker 自动审查待处理案件，提供理由、可疑度建议与数值核对，不能自行封禁或代替人工确认。
- AI 输入为格式化 JSON：案件相关的已保存事件、冻结规则、统计、审核与执行信息；输出也按 JSON 约定解析。不发送图片、数据库密码或 RCON 密码，不声称能补出未采集的伤害日志。超过输入上限明确报错，不静默省略证据。
- [JSON／JSONL 历史导入](integrity-import.zh-CN.md)提供字段模板、校验、待审核、批准和撤销流程。外服记录不伪装成本服实时事件，不混入委员会当前服务器精准度分布。
- 可选 Steam Web API 提供公开账号及 VAC／Game Ban 信息；它不能补齐 Kill Feed，也不代表 WARDOGS 官方完整生涯。网页举报和 Discord 案件通知可按组织配置使用。

| 强弱阵营平衡 | 领先方默认须比另外两方都高超过 40 分；与最低分方交换各 3 人，先 KPM 后 KD 排序 | [规则说明](skill-balance.zh-CN.md)；等待新鲜死亡事件，不在活着带装备时强制换边 |

原有欢迎消息、定时广播、队杀规则、名称过滤和入服账号风险规则仍使用各自设置。

### 赛后六个奖项

| 奖项 | 依据 |
| --- | --- |
| 本局 MVP | 最高 KD，有击杀才参加，死亡按至少 1 计算分母 |
| 最佳单次多杀 | 同一游戏时间戳最多有效击杀，至少 2 杀；是多杀近似值 |
| 最佳一命连杀 | 一条命中最多有效击杀，死亡终止连杀 |
| 本场赚钱最多 | 观测到的金钱净增，不含无法恢复的已消费金额 |
| 本场最富玩家 | 赛末最后观测到的持有金钱 |
| 在线最久 | 本局累计已观测在线时间 |

每项只选一人，并列随机抽一人；本局抽签结果保存，重试不重抽。无有效数据的奖项跳过。同一人可获多个奖项。工程／医疗贡献尚无已接入可靠数据源，不编造最佳贡献奖。

## 常见误解

1. **RCON 已连上，为什么 KPM 还是空？** RCON 是面板主动连接游戏服；Kill Feed 是游戏服主动回传面板。须分别配置并确认真实事件到达，详见[安装第 6 步](install.zh-CN.md#第-6-步有游戏服后再接入)。
2. **换了一张地图，为什么专家仍未知？** 换图不会凭空生成基线、生涯或样本；不同专家有各自的数据门槛，缺一项不代表所有资料都没有。
3. **AI 写可疑是否会封禁？** 不会。AI 建议、统计投票、直接踢出、管理员确认违规是不同路径。
4. **所有要求都已实现吗？** 游戏聊天读取与 `!report`／`!BAN`、客户端扫描、官方完整生涯、未提供的工程医疗贡献都不能宣称可用。已知网络延迟也不能推导玩家 IP。

## Steam 生涯时长分布

数据分析页按所选范围（24 小时／7 天／30 天）内到访本服的 SteamID 去重，展示 WARDOGS 累计游戏时长。人数折线按自适应等宽小时区间合并，最多 20 个区间；可切换累计占比，查看 80% 分位数（按原始分钟加权排序、最近秩计算）。表格从未知开始，随后按小时区间递增。

配置 `STEAM_API_KEY` 并重启服务后，Worker 会逐步查询最近 30 天出现过的玩家，每 5 秒最多 2 个请求，结果缓存 24 小时。首次覆盖全部玩家需要时间；页面每分钟刷新。未公开／未返回、待查询、失败及过期数据都不作为 0 小时，不进入百分位分母。80% 只描述公开样本，不保证代表全部玩家。该数据不参与风控或自动处罚。

来源为 Steam 官方 [GetOwnedGames](https://partner.steamgames.com/doc/webapi/iplayerservice)，只查询 [WARDOGS（1867240）](https://store.steampowered.com/app/1867240/WARDOGS/)。这属于 Steam 累计游戏时间，包含菜单和挂机时间，并非纯战斗时长。API Key 只存服务端，页面仅接收聚合结果。
