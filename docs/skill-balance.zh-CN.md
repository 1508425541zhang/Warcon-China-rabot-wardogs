# 自动强弱阵营平衡

入口：服务器 → 自动化 → 强弱阵营平衡。默认关闭，启用后选定3对玩家，逐人等待新的被其他玩家击杀事件，再尝试调队。

## 什么时候进入候选计划

1. 当前是有明确阵营积分的三队对局。
2. 最高分队必须比**另外两队各高出超过40分**。例如100／60／20不触发，101／60／20可以触发。可以在设置中调高到60分或更高。
3. 默认开局及面板重新建立观察后的300秒内不调队；参数允许180～1800秒。地图结束、切换、当前状态过期时不调队。
4. 领先和落后阵营必须唯一；两个落后队并列最低分时等待分出先后。
5. 两边各有至少3名连续在线满180秒、近期没有Warcon调队记录的可用玩家，并且三对交换都能改善弱队的KPM／KD排名。
6. 当前对局有覆盖180秒的Feed记录，最近事件没有超过60秒，并且事件时钟与当前对局相符。

## 选哪六个人

- 领先队取KPM最高的3人；KPM相同，KD较高的优先。
- 最低分队取KPM最低的3人；KPM相同，KD较低的优先。
- 两项均相同时用SteamID稳定排序，不随机反复换人。
- KPM = 最近180秒已接收的有效击杀数÷3。包括枪械、载具等，排除自杀和已知队杀；不要求属于纯步兵击杀。
- KD = 本局已接收的有效击杀数÷max(本局死亡数,1)。这是本局Feed数据，不是生涯KD；缺少当前对局数据时不运行。

一份计划是3对、共6名玩家，中间阵营不动。每局最多一轮计划，选人后名单冻结。双方可以先后死亡、分批完成交换。

## 死亡事件触发

只接受选人后、同一对局和服务器实例、接收不超过5秒的被击杀事件。自杀、已知队杀、重复或过期事件不触发；发现该玩家随后又产生击杀时不使用之前的死亡事件。

直接 PATCH 玩家阵营，不调用原有 changeTeam 中的 /kill 强制死亡动作。没有新的死亡事件就继续等待。死亡事件存在网络延迟，这一方式按事件触发，不能保证游戏端执行瞬间尚未重生或读取其装备。

目标阵营满员时等待后续死亡事件；接口结果未知或进程中断则停止该对自动重试，请人工核对。未开始交换的对仍要求分差成立；一侧已确认交换后，另一侧在后续死亡时可完成配对。关闭、保存新设置或换图会停止剩余计划，本局不重新选人，已交换玩家不会被强制调回。

页面显示最近20局计划和每位玩家的等待、确认及未知状态。升级后功能仍默认关闭。
