# 计划任务

入口：服务器 → 自动化 → 计划任务。管理员先启用插件，再创建任务；也可以先保存任务后启用。

任务执行一次。可选指定日期时间（界面按北京时间 UTC+8 输入，API 必须携带时区），或当前对局结束后的新一局。同图重新开局也算新一局；同一局内重启面板不会执行下一局任务。

可计划的操作：

- 开启武器／载具来源限制：保存此次任务选定的来源 ID 或整类名单，到期替换限制配置；需要 Kill Feed。处罚方式沿用武器限制插件。
- 关闭武器限制：保留已有来源名单。
- 禁止或允许玩家自行换阵营：使用现有换边限制插件，保留保护时间、阵营容量及授权调队机制。
- 启用或关闭一条现有自动化规则：选择当前服务器的规则，不改变规则参数；切换高延迟规则时清空其计数。
- 服务器广播：最多200字，通过持久发送队列执行，未确认的发送不会自动重试。

如需一个临时限制，可创建两项任务：第一项开启，第二项在指定时间关闭。插件暂停或服务器观测不健康时不执行；恢复后错过超过5分钟的任务会记录为跳过，不补执行。下一局任务也不会在已经开始超过5分钟的对局中补执行。

创建和执行时均检查操作权限；创建者删除、停用、失去所需权限，或所选规则删除，任务跳过并记录原因。创建者必须使用管理员账号会话，组织 API 密钥不能保存计划任务。服务器之间的计划相互隔离。

配置和执行回执持久保存，按服务器加锁，配置修改使用版本号避免覆盖并发修改。最多100项未完成任务，自动保留最近100项完成回执，界面每页20条。审计日志另按面板现有保留策略处理。关闭计划设置窗口会停止该窗口的状态轮询，已启用的后台任务继续按计划工作。

## HTTP API

`GET /api/servers/:id/scheduled-tasks` 返回 `revision`、`enabled` 和任务记录。

`POST /api/servers/:id/scheduled-tasks`：

```json
{
  "revision": "使用 GET 返回的版本号",
  "operation": "create",
  "task": {
    "name": "下一局禁止自行换边",
    "when": { "kind": "next_match" },
    "action": { "kind": "faction_lock", "enabled": true }
  }
}
```

指定时间使用 `"when": {"kind":"at","at":"2026-10-02T20:00:00+08:00"}`。

其他动作：

```json
{"kind":"weapon_restriction","enabled":true,"causes":["Id.Item.SVD"],"groups":[]}
{"kind":"trigger","triggerId":"现有规则 ID","enabled":false}
{"kind":"broadcast","message":"下一局开始，禁止自行换阵营。"}
```

开关插件：`{"revision":"...","operation":"settings","enabled":true}`。

取消待执行任务：`{"revision":"...","operation":"cancel","taskId":"任务 ID"}`。广播已经开始发送或完成后不能取消。

清除完成回执：`{"revision":"...","operation":"clear_finished"}`。不会删除待执行任务。

版本冲突返回409，刷新后重试；无权限返回403。后台执行回执和自动化发送结果分别说明配置生效与游戏服务器是否确认执行。
