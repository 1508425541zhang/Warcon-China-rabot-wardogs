# 组队控制：疑似大队名单

入口：服务器 → 自动化 → **组队控制**。默认关闭，只列出疑似组队名单，供管理员点击玩家档案核对；不自动踢出、封禁、换阵营，也不影响风控评分。

## 设置步骤

1. 选择“不执行”“手动扫描”或“自动扫描并列出名单”。
2. 选择“结构化模式”或“AI参与模式”。
3. 填写昵称前缀长度，默认4，允许2～16个字符。
4. 填写相似度阈值，默认70%，**严格大于**才通过。
5. 填写同组触发人数，默认至少4人。“超过3人”对应填写4。
6. 点击保存。手动模式点击“按已保存配置扫描”；自动模式由后台玩家轮询触发，每65秒最多扫描一次。
7. 点击“刷新结果”查看最近一次名单和扫描时间。

名单仅代表扫描时的阵营与昵称，玩家离线、改名、换阵营后以新扫描为准。关闭功能后旧结果仍保留，便于核对；不再生成新扫描。

## 匹配算法

昵称使用Unicode NFKC标准化并统一小写，删除空格、标点、表情和其他符号，保留文字（含汉字）与数字，取前N个字符。清理后不足N个字符的昵称不参与，避免短名字被误当成统一前缀。

相似度为 `100 × (1 − 编辑距离 / 较长前缀长度)`。前4字符替换1个字符的相似度为75%，会通过默认70%阈值；恰好等于阈值不通过。

只比较当前有效阵营中的玩家，SteamID去重。同组每两人都必须超过阈值，不通过“相似关系传递”扩大名单。按前缀与SteamID排序后确定分组；这是确定性的保守分组，重叠的候选组可能不会全部显示。昵称相似不能证明真实组队。

## AI参与

复用组织的风控AI审查接口、加密密钥、模型与输出上限。没有候选组不调用模型。仅发送候选组的昵称、SteamID、阵营、标准化前缀和相似度JSON，不发送密码、其他日志或图片。

AI返回每组的辅助判断与中文理由：疑似统一标记、无法确定、可能为巧合。输出必须符合JSON格式、逐组对应且无额外组；不合格响应显示AI暂不可用，结构化名单保持原样。昵称内容被明确当作不可信数据，不能作为指令。

与案件AI共用组织65秒请求间隔及每日自动请求预算；组队扫描使用自己的执行开关，不由案件自动初审开关控制。相同名单且配置未变化时复用上次成功结果。额度耗尽、连接失败或配置缺失时继续展示结构化结果，下次扫描可重试。AI等待不会阻塞游戏服务器轮询。
