# 外服历史数据导入：JSON／JSONL

此功能供组织 Owner 把其他服务器的历史击杀记录导入实验性统计风控。上传后先进入“待审核”，批准后才计算外部基线。导入数据不会写入本服实时击杀、排行榜或玩家处罚记录。批准可撤销，撤销后立即重新计算基线。

## 第一步：整理数据

每一行代表一次**真实的步兵击杀事件**，必须有稳定且唯一的 `eventId`。同一来源服务器再次上传同一事件会被拒绝。只导入最近 30 天、至少 10 分钟前发生的记录。不要把合成统计值、演示数据或仅有 K/D 汇总的数据伪装成逐次击杀。

可用格式：

- `.jsonl`：每行一个 JSON 对象。推荐，便于导出和定位出错行。
- `.json`：JSON 数组，或 `{ "events": [ ... ] }`。

单个文件最多 8 MiB、10,000 条；大文件按事件拆分成多个批次。文件编码为 UTF-8。

## 第二步：按标准字段转换

下面是**字段示例**；请把时间、Steam ID 和局编号替换为真实记录。过期的示例时间不能直接上传。

```json
{
  "eventId": "kill-000001",
  "eventAt": "2026-09-24T12:00:00.000Z",
  "instanceId": "server-start-001",
  "matchId": "round-001",
  "eventTime": 421.5,
  "map": "Kavkazi",
  "killerSteamId": "76561198000000888",
  "victimSteamId": "76561198000000999",
  "killerFaction": "Blue",
  "victimFaction": "Red",
  "cause": "Id.Item.AK74M",
  "distanceM": 85.4,
  "headshot": false,
  "penetration": false,
  "playerCount": 42
}
```

| 字段 | 含义和要求 |
| --- | --- |
| `eventId` | 原服务器中稳定唯一的事件 ID；重导时不能换 ID。 |
| `eventAt` | 事件绝对 UTC 时间，ISO 8601，以 `Z` 结尾。 |
| `instanceId` | 原服务器本次启动的标识。 |
| `matchId` | 本局唯一编号，同一局使用同一值。 |
| `eventTime` | 本局开始后经过的**秒数**，不是 Unix 时间戳。 |
| `map` | 原游戏地图代码；同地图名称须一致。 |
| `killerSteamId`、`victimSteamId` | 各 17 位 Steam ID，且不同。 |
| `killerFaction`、`victimFaction` | 击杀当时的真实阵营，必须不同。 |
| `cause` | 游戏原始武器 cause，形式如 `Id.Item.AK74M`。未知枪械须先到“武器映射”确认是步兵武器。 |
| `distanceM` | **米**。未知填 `null`；不能把厘米直接填进来。 |
| `headshot`、`penetration` | 真实布尔值 `true`／`false`，不能填字符串。 |
| `playerCount` | 击杀当时服务器人数，1～200；未知填 `null`。 |

例如原始距离字段是厘米，转换时使用 `distanceM = distanceCm / 100`。无法确认单位时填 `null`。不能根据玩家表现推测爆头、穿透、阵营或人数。缺少必需字段的事件应从导出文件中排除，并在交审记录中说明排除数量与原因。

## 第三步：上传并交审

1. 登录管理面板，以组织 Owner 身份打开“组织社区风控设置”。
2. 在“外服历史数据导入与审核”填写固定的来源服务器标识，例如 `community-eu-01`。同一原服务器以后都使用这个标识。
3. 选择 `.json` 或 `.jsonl` 文件，点击“上传并暂存”。
4. 核对页面上的记录数、时间范围、地图、武器和已知人数数量；检查原始导出是否获授权且可追溯。
5. 点击“审核批准”。批准前不会参与风控。误批时点击“撤销批准”。

上传时校验每条事件的时间、身份、阵营、武器和单位。整个文件一次处理：有一条不合格则不导入。系统保存文件 SHA-256、来源、操作人、审核时间和批次状态供审计。重复文件或同一来源中重复的 `eventId` 不会被导入。

## 第四步：观察效果

本服基线与外服基线分开计算。相同指标优先采用样本足够的本服基线；本服不足时，才回退到已批准的外服基线。外服至少 30 个**可比的 180 秒窗口**可用于实验性百分位和人工案件观察；本服需要至少 200 个可比窗口。上传 30 条击杀不等于 30 个窗口。同枪械爆头率需窗口内该枪至少 10 次击杀；最远击杀需至少 3 次。

统计自动处置仍要求该指标至少 **5,000 个可比窗口**，且受在线人数、独立证据、开关和处置上限控制。少量外服数据可以先帮助管理员观察分布，但不能单靠少量数据触发踢出。图表会显示“审核通过的外服历史”来源。外服数据质量由审核人负责；审批只表示允许作为实验性参考，不证明记录真实。
