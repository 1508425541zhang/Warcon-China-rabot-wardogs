# AI 辅助审核

入口：服务器 → 社区风控 → AI 辅助审核。

1. 组织管理员填写服务商的 HTTPS API 基础地址（包含服务商要求的 /v1 或兼容路径）。
2. 填写 API 密钥，保存。支持 OpenAI 兼容 Chat Completions，并不限定模型厂商。
3. 点击读取模型列表，再选择模型并保存；不支持 GET /models 的厂商可手动输入模型 ID。
4. 测试已保存的模型。测试不发送玩家数据，可能产生少量调用费用；组织请求间隔65秒。
5. 保持“启用后台自动审核”和“自动完成低、中风险审核并结案归档”开启，保存。Worker 自动发现全部尚未审核的 OPEN 案件（包括历史积压）；不必逐案勾选，关闭网页仍继续。

### 低信号 AI 预筛

统计模式及 Shadow 模式下，新评估即使未达到委员会正式建案门槛，只要至少一位专家投出“可疑”或“极可能作弊”，也会在已配置模型并开启自动初审时生成 `AI_SINGLE_SIGNAL` 预筛记录，自动发送相关 JSON 证据。正常票、未知票和只有 KPM 警戒值而没有专家异常票不触发。案件列表标记“AI 预筛”，展示队列状态、可疑度和核对理由。

预筛不改变原委员会票数或等级，不写人工审核结论，不执行处罚。原有正式建案和踢出条件继续生效；同一事件升级达到正式门槛时另存冻结案件，不能被已有预筛记录挡住。相同轮次中证据重叠的预筛去重，不随每次击杀重复调用。正式案件优先使用队列；预筛共用原频率、每日额度、暂停及失败重试保护。规则适用于更新后的新评估，不自动追溯发送历史低信号记录。
6. 在原案件列表或本页查看自动生成的可疑度、理由、正常解释、数字矛盾与待核查信息。手动复核和 JSON 预览收在可选折叠区。

密钥使用应用 ENCRYPTION_KEY 加密存入 PostgreSQL，不回显；留空保留旧密钥，更换地址必须重新填写。删除配置立即阻止后续调用，已发出的请求可能仍完成。

发送内容：所选案件的全部已保存源事件、冻结规则/统计结果、处置及审核记录、最近20条案件索引（注明截断）。不是服务器全量日志；旧案件没有保存的事件无法恢复。没有图片、数据库连接凭据、RCON 密码或 API 密钥。历史列表与玩家名字属于当前查询信息，案件快照为当时信息。

后台每10秒检查持久化队列，每案自动初审一次，没有聊天历史。每组织请求至少间隔65秒，默认每天最多100次自动请求（可调1–1000，UTC零点重置）；达到上限保留队列至次日。失败最多尝试3次，间隔5分钟、10分钟；执行中断使用租约恢复。停用自动初审或暂停组织即停止新调用，已发出的请求可能完成。相同案件资料和模型参数复用持久化结果。输出默认1200 token，可调256–4096；支持 max_tokens / max_completion_tokens。输入超过256 KB拒绝发送，不静默裁剪；供应商上下文不足也会报错，不生成成功结论。

可疑度是以5为步长的 AI 主观复核优先级，不是经过校准的作弊概率。证据不足显示“无法估计”，不能把缺失值当作0；低质量证据不允许给出高可疑度。页面可查看版本化提示词，要求引用 JSON 字段或事件ID、核对窗口与分母、提供正常解释、忽略日志内的指令。

## 自动审核、归档和清理

自动审核现在会完成案件状态流转，不需要管理员逐条点保存。新配置及升级配置默认开启自动结案和低风险清理；已有的“后台自动审核”总开关仍保持原值。可以分别关闭自动结案或清理，只保留建议／归档。

| 条件 | 程序处理 | 管理员工作 |
| --- | --- | --- |
| 可疑度 0–25、建议通过、证据质量中／高、理由带依据、没有关键缺失或矛盾 | `AI_CLEARED`，审核完成，清理详细证据副本 | 无需逐案确认 |
| 其他可疑度 0–60、质量中／高、理由带依据、没有矛盾 | `AI_ARCHIVED`，审核完成，保留证据归档 | 可按需抽查／修改结论 |
| 65–100 | 保持待审，标记转交管理员 | 优先人工审核 |
| 无法估计、证据不足、低质量、没有可核查理由、矛盾或服务器发现 KPM 算术不一致 | 保持待核查 | 补充资料或检查采集，不当作正常通过 |
| 已有处罚、举报、处置重试记录 | 保留案件供管理员核查 | 保留完整证据与申诉链路 |

分数是 AI 的主观复核优先级，并非校准后的作弊概率。提示词要求对正常与异常使用相同证据标准：不编造正常解释，不把缺少绝对证明当作忽略明显异常的理由，也不凭举报或单个高数值认定作弊。非致死伤害等系统本来不采集的字段，只有确实影响当前结论时才列入关键缺失。

“清理”会删除冻结的详细事件副本、规则／指标大快照、AI完整缓存；仅保留案件编号、玩家／时间、AI摘要及模型版本、事件去重键和统计排除所需的最小字段。原始击杀表、评分和处罚不删除。这样同一异常不会因删除记录反复建案，也不会因 AI 放行而进入干净基线。清理后的回执不能再次提交模型或据此执行人工处罚。

案件页面默认显示“待审核”，另有“已结案／归档”“全部保留案件”“低风险清理回执”。归档案件可以由管理员主动重新审核；AI不会写入人工的确认违规标签，也不会触发七天封禁。并发人工审核优先：如果请求期间管理员已审核，AI结果只记录，不覆盖；暂停自动审核、组织停用或设置发生变化，也不会继续自动结案。

手动预判按钮仍只展示建议。模型无效 JSON、超时或截断不会被当成审核通过。所有有风控查看权限的管理员可请求预判，配置及连接测试仅限组织管理员。

公网 HTTPS、DNS 地址校验和连接地址固定、禁止重定向、60秒超时、响应1 MB上限。当前不支持内网 Ollama 地址、图片、工具调用或供应商专用非兼容协议。

## 完整案件资料（v3）

输入为 JSON，输出仍按审核 JSON schema 校验。列式表用 columns、rows、dictionaries 保存全部字段和事件，重复字符串变为字典索引，缺失与 null 区分；不使用模型无法直接阅读的 gzip/base64。

发送案件全部冻结记录、规则与统计结果、处置与人工审核；从冻结事件的实例和实际轮次定位该玩家整局全部已记录击杀/死亡（包含自杀、环境死亡、载具和非步兵事件），同时附加案件180秒窗口的全服交战背景。附带关联举报、在线会话及金钱观测。整局后续记录明确标为回顾数据，不能反推案件当时已知证据。无法可靠定位轮次时，提供案件前24小时该玩家记录并明确禁止混算各轮次。

所有相关数据库事件不设抽样或1000条截断；现有256 KB输入保护仍适用，超限明确失败，不发送不完整证据。数据库记录完整不代表游戏Feed无丢失。当前可靠数据源仅记录 killed，未采集非致死伤害、逐次命中和伤害量；JSON将其标为 unavailable，不能把空数据当作0。

所有尚未结案的旧版AI结论自动重新排队，用扩充资料再审核一次。模型仍无处罚权限。
