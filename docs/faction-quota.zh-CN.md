# 50V50 模式与阵营人数配额

入口：服务器 → 自动化 → **50V50 模式 · 阵营人数配额**。默认关闭，初始配额蓝50／红50／绿0。三个快捷预设分别关闭蓝、红、绿，另外两方各50；也可填写其它配额（0～100整数，至少两方开放，总和不超过100）。

0代表该方不留玩家，剩余在线人数按开放方的配额比例分配。例如50／50／0在100人都已选择阵营时为50V50，80人时为40V40，奇数时相差1人。配额只是上限和分配比例，不生成玩家；游戏本身仍须提供相应总容量。

## 官方接口依据

2026-10-01核对官方控制台的 [api.js](http://rcon.wardogs.com/js/api.js)、[配置示例](http://rcon.wardogs.com/ServerSettings.ini)，并只读检查OPEN1实服 `++Wardogs+Live-CL-507060` 的 `/v1/capabilities`、`/v1/status`、`/v1/config`：

- 官方支持 `PATCH /v1/players/{id}`，请求 `{faction: 实际阵营名}`；官方控制台随后调用 `POST /v1/players/{id}/kill` 使玩家在新方重生。本功能复用面板同样的动作。
- `GET /v1/status` 提供 `factionScores[].name/colorHex`；按RGB主色映射实际名称，禁止按数组顺序猜测。实服蓝Lonestar（#4CB1EF）、红Valkyra（#FA503E）、绿Manticore（#1DD65C）。身份或颜色不唯一时暂停。
- 官方没有逐阵营人数上限或隐藏某个阵营入口的设置。`/Script/WDGame.WDGameStateSession` 提供 `bLockOverpopulatedTeamsConfig`、`OverpopulatedTeamThresholdConfig`，均下一局生效。开启人数差加入锁会让另外两方相对0人阵营持续超额，因此启用配额时将第一项改为false，等待当前局结束后运行。
- 配置使用既有读写路径，保留未编辑内容和凭证，使用revision／If-Match保护并回读确认。关闭时只在该项仍为本功能写入的false时恢复原值，保留其它管理员不同的值。不会改MaxPlayers、预留位或重启实服。

这是使用官方接口维持阵营人口的面板自动化，游戏仍保留第三阵营、基地、计分等原有规则。不能通过现有官方API原生删除第三阵营。第三方入口暂时可以选择，玩家将被自动调往开放方；不会宣称选择菜单已被硬锁。

## 执行行为

启用要求自动化管理、玩家调队和配置应用权限。先关闭“禁止自行换边”“强弱阵营平衡”；如果它们之后又开启，配额调队暂停。开局／面板重连保护默认60秒，可设置30～600秒。

仅在取得工作进程所有权、当前同图对局、健康可信的新玩家快照与30秒内状态时执行。在线人数不足时按配额比例安排；奇数时保留已有较多人方，避免反复调队。未选阵营的玩家留在选择界面。优先移动需调整阵营中击杀较少的玩家。每次只调一人，获得新的阵营快照确认后再继续；单玩家120秒冷却。失败或未确认时保存明确状态，不在两分钟内重复操作该玩家。进程重启后读取持久记录，等待未确认请求核对，不盲重发。

若已有阵营人数超过配额总和，显示没有空位并暂停，不踢人、不封禁。任何调队请求均保存动作记录，并进入审计。UI“已确认”必须来自下一次快照，HTTP成功仅显示待确认。

设置保存在`site_settings`的每服务器独立键，关闭与配置准备中不执行调队。需要保留分数模型和QQ机器人既有部署；本功能无数据库迁移。

## 验证范围

纯策略测试覆盖三种关闭方、0～100所有人口、奇数稳定性、配额耗尽、身份与颜色缺失，以及输入边界。隔离数据库集成测试覆盖权限、配置冲突、只改一个游戏配置值并恢复、等待换局标志、快照确认后继续调队、关闭和不健康时无副作用。

实服的官方能力和设置已核验。上线保持关闭，不在正在进行的对局中批量调动玩家；实服达到50人／方的最终效果须在用户启用、换局且人数足够后观察。若游戏额外拒绝调队，页面会保留结果待核对，而不会冒充成功。
